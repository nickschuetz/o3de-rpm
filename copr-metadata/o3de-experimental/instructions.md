**For end-user testing use [hellaenergy/o3de](https://copr.fedorainfracloud.org/coprs/hellaenergy/o3de/) (stable) or [hellaenergy/o3de-stabilization](https://copr.fedorainfracloud.org/coprs/hellaenergy/o3de-stabilization/) (during a pre-release window).** This repo is for the packagers' own validation; RPMs here track the bleeding-edge development branch and carry in-flight changes.

**If you're here anyway** (e.g. engine contributors on the development branch, or packagers validating the native-Wayland Editor path):

    sudo dnf copr enable hellaenergy/o3de-experimental
    sudo dnf install o3de2610 o3de2610-devel

**Built for Fedora 44, Fedora 45, rawhide and CentOS Stream 10** (all four chroots since 2610.0-125). On CentOS Stream 10, enable CRB and EPEL 10 first (`sudo dnf config-manager --set-enabled crb` and `sudo dnf install epel-release`), and name the repository when enabling this project: `sudo dnf copr enable hellaenergy/o3de-experimental centos-stream-10-x86_64` (a plain `dnf copr enable` looks for an `epel-10-x86_64` repository, which this project does not have).

The `o3de-dependencies` repo auto-enables alongside this one (no separate `dnf copr enable` needed). `o3de2610-devel` is part of the install line above on purpose. It carries the engine's static libraries, and every project build links its launchers against them (`AzGameFramework`, `Launcher.Static`), so Project Manager cannot build a project without it. The main package also Recommends it, but naming it explicitly keeps it installed where weak dependencies are off (containers, Toolbox/distrobox, minimal images, `install_weak_deps=False`).

**What is this:** O3DE experimental builds from upstream's `development` branch (Qt6, same source as [hellaenergy/o3de-development](https://copr.fedorainfracloud.org/coprs/hellaenergy/o3de-development/), with the same bundled Qt 6.11.2 and the same 21-library system-swap set from 2610.0-123). This channel validates forward-looking, riskier changes that aren't ready for community testers. **Current focus: a native-Wayland preview.** The fedora-44 and fedora-45 chroots build with the `wayland` and `wayland_ui` bconds: the engine's Wayland window and Vulkan surface path is compiled in, and Patch0022 adds Editor UI fixes for native Wayland and XWayland (window move and tile snapping, floating panel move and dock, viewport and camera fixes, Vulkan surface fixes for the Particle Editor and the standalone Atom tools). Patch0022 is a local carry that has not been proposed upstream yet. These packages have been built but not yet installed and hand-tested, so expect rough edges. The stock builds on the other channels support X11 and XWayland only and must not be forced onto native Wayland with `QT_QPA_PLATFORM=wayland` (the Editor crashes at startup, o3de/o3de#19835, on any GPU vendor; native Wayland support is tracked upstream in o3de/o3de#18513); that restriction is what this channel is working on.

**Release game export:** the current Wayland builds here do not carry the `monolithic` bcond, so a release-config game export (`No monolithic artifacts are detected in the engine installation`) does not work from this channel. The monolithic (release, static) permutation graduated to [hellaenergy/o3de-development](https://copr.fedorainfracloud.org/coprs/hellaenergy/o3de-development/) on 2026-08-03; use that channel for release exports.

The package follows a **versioned-major naming convention** (`o3de2610` for the 26.10.x line) installing to `/opt/O3DE/<DISPLAY_VERSION>/`, the same path pattern as upstream's `.deb` and Windows installer. Multiple majors can be installed side-by-side (upstream's `.deb` installs one release at a time, because every release has the package name `o3de`). Each major's `engine.json` ships `engine_name: "o3de"` (as in upstream's source `engine.json`; upstream's `.deb` installs as `o3de-sdk`); the manifest at `~/.o3de/o3de_manifest.json` can register several majors at once, and a project configures against the newest registered engine it accepts (new projects accept any major); to keep a project on an older major, pin it with `<install-prefix>/scripts/o3de.sh edit-project-properties -pp <project> --user --engine-path /opt/O3DE/<version>`.

**Subpackage layout**, same as the other channels: main `o3de2610` (runtime + project-build essentials); `o3de2610-devel` (engine static archives; every project build links its launchers against them, so install it with the main package); optional `o3de2610-debug` (debug-config binaries, only when `--with debug` is set, NOT activated in this channel). Project-build `*-devel` system packages pulled in via Recommends; opt out with `--setopt=install_weak_deps=False`. Note the inverse: containers, Toolbox/distrobox, and minimal/server images that already run with `install_weak_deps=False` will skip the toolchain, so project builds fail on missing compilers/headers until you backfill with `sudo dnf install $(rpm -q --recommends o3de2610 | awk '{print $1}')` (naming the Recommends explicitly, since a plain `sudo dnf install o3de2610` no-ops when it is already installed).

**`o3de2610-cli` PATH wrapper**: `/usr/bin/o3de2610-cli` forwards to `/opt/O3DE/26.10.0/scripts/o3de.sh` so the upstream Python CLI (project / gem / engine management, ~25 sub-commands, including `export-project`) is reachable on `$PATH`.

**Gems with system runtime dependencies:** some o3de-extras gems (ROS 2 family, AudioEngineWwise, OpenXRVk, etc.) require external system runtimes the engine RPM does not bundle. Project Manager surfaces the requirement on each gem's information icon. See [`docs/GEMS_WITH_SYSTEM_DEPS.md`](https://github.com/nickschuetz/o3de-rpm/blob/main/docs/GEMS_WITH_SYSTEM_DEPS.md) for install paths and the project-build workflow.
